# 2026-11-01

## 新增：预约排班模块

在现有「智慧车店」上开发预约排班，需求：看师傅×时段的时间表、判断时间冲突、预约项目可关联客户信息。

### 产品口径（已与用户确认）
- 师傅 = 员工账号 + `canBeTechnician: true` 标记（不新建师傅表）
- 时段粒度 **60 分钟**，营业时间 08:00–19:00（共 11 档），起约对齐 30 分钟
- 预约可**一键转开单**（生成 order + purchased_goods，回写 orderId）
- 仅店内员工代客录入，不做客户端自助

### 落地结构
- 集合 `appointment`（schema 关闭客户端直读，只能走云函数）
  - technicianId/Name、memberId、carInfoId + 客户姓名电话车牌快照、items[]、startTime/endTime/duration、status、orderId
  - status: 0 待到店 1 施工中 2 已完成 3 已取消 4 未到店；**只有 0/1 占用时段**
- 云函数 `appointment_api`（单函数 action 路由）：board / detail / byMember / save / status / toOrder / setTechnician
  - 鉴权沿用会员模块口径：只信 userId，服务端反查 enterpriseId
  - 冲突在服务端二次校验（409 + conflicts 明细）；已开单的预约禁止改时间、禁止取消
- 纯逻辑 `lib/schedule.js`（云函数）+ `common/utils/schedule.js`（前端轻量同源版）
  - 所有时间按北京时间显式换算，不依赖容器/设备时区（云函数是 UTC）
- 页面 `pages/appointment/`：board（时间表+清单双视图）、edit、detail
- 客户反查：`pages/member/detail.vue` 增加「预约记录」区块（action byMember，分 upcoming/history）
- 入口：首页与 home 页宫格「预约排班」（图标 icon-guazhangmingxibiao）
- 配置：`app_config` 集合 key=`appointment_config` 可改营业时间/档位/对齐粒度，不建页面
- `goods` 表加 `duration`（预计分钟），选项目自动累加时长

### 踩坑 / 注意
- 排班表左列固定 + 右侧 scroll-view 横向滚动；行与表头必须 `box-sizing: border-box`，否则 border 逐行累积导致左右错位
- 档位索引 0 = 08:00-09:00，测试断言别把 09:00 当成 index 0
- 云函数容器时区是 UTC，任何 `new Date().getHours()` 都会错 8 小时
- 老 mock 缓存不会自动补新 user，需 resetMockData 才能看到演示技师

### 验证
- `node tests/appointment-schedule.test.js` 47 项
- `node tests/appointment-wiring.test.js` 63 项（页面注册/API 名称/跳转路径/schema/action）
- 另有一次性 mock 冒烟（已删）：board→冲突拦截→保存→吸附→开单→幂等→状态流转 21 项
- 未跑 uni-app 编译：项目为 HBuilderX 工程，无 package.json，只能由用户在 HBuilderX 里运行

## 迭代：补「跨天预约」+「工位容量」

用户要求补上第一轮遗留的两项。

### 跨天预约
- `MAX_DURATION_MINUTES` 12h → **24h**（18:00 接车、次日 10:00 交车的贴膜/大修才排得下）
- 看板取数从「startTime 落在当天」改成「**区间与当天有交集**」：
  - 云函数多取前一天（`startTime >= dayStart - DAY_MS`），再用 `overlapsDay()` 二次过滤
  - `slotSpanOf(a, config, dayStart)` 支持 dayStart：昨天开始的单 `startSlot=0` + `startsBeforeDay`；今天干不完的 `clippedSpan` 截到末档 + `endsAfterDay`
- 展示：新增 `boardTimeText`（次日显示「昨日 18:00-次日10:00」，跨天显示「18:00-次日10:00」）；看板块上加「续」角标；清单视图单独一行显示跨天时间
- 汇总口径：`summarize(list, { dayStart })` 按当天营业区间裁剪占用分钟，跨天单不会把昨晚 8 小时算到今天；新增 `crossDayCount`
- 表单：`endLabelOf()` 输出「次日 02:00」而不是回绕成 26:00；时长档补到 720 分钟
- 提示：`validateDraft` 跨天/超关门只 warning 不拦截，前端保存后弹窗展示 warnings

### 工位容量（举升机）
- 配置项 `bayCount`（默认 3，**0 = 不约束**），写在同一个 `appointment_config` 里
- 规则与师傅冲突**分开判断**：`bayPlan(list, draft, config)` 取与草稿重叠的占用单，条数即最大并发数（一维区间两两相交必有公共点）
- 工位号 `bayNo` 自动补空位：先认已有 `bayNo`，历史单没号按开始时间顺序补；表单可手工指定，再点一次退回自动
- 保存时满员返回 409 + `bayFull: true`；`detectBayConflictPairs` 把「同工位重叠」也标红
- 看板：`bayLoad()` 逐档统计，顶部工位条显示「工位 3 个 · 今日峰值 2 · 09:00-10:00」，排满时变成橙色警示
- 详情页显示「2 号位 / 共 3 个」；`user` 与 `goods` 之外新增 schema 字段 `bayNo`（int）

### 验证
- `node tests/appointment-schedule.test.js` **78 项**（含跨天格位、次日裁剪、工位补位/满员/legacy）
- `node tests/appointment-wiring.test.js` **84 项**
- 一次性 mock 冒烟（已删）10 项：跨天单次日可见+时间冲突、三单占 1/2/3 号位、第四单 409 bayFull、取消后释放工位

### 注意
- 前端 `common/utils/schedule.js` 只镜像页面要用的部分（bayPlan/endLabelOf/crossesDay），`slotSpanOf`/`bayLoad`/`summarize` 留在 mock 与云函数里各自实现——mock 扮演服务端，允许重复但口径必须一致
- `bayPlan` 返回必须带 `items`，否则满员时的提示文案取不到列表直接抛异常
