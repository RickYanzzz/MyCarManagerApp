## 修复：消费开单「拍照识别车牌」识别不出来（百度 OCR）

### 根因
- 真正生效的 OCR 代码在 `components/nav-header/nav-header.vue`（`type='carNumber'` 的相机按钮）
  —— 注意：`common/api/image_ocr.js` 与云函数 `get_image_ocr_token` 都是**旁路死代码**，前端未调用
- `pathToBase64()`（`common/js/image_tools.js`）在 App/小程序/H5 三端返回的都是**带 `data:image/xxx;base64,` 编码头**的字符串
- 百度 OCR 的 `image` 参数要求为**纯 base64（须去掉编码头）**；带编码头会返回 `{"error_code":100,"error_msg":"Invalid parameter"}`
- 导致 `words_result` 为空 → `res.data.words_result.number` 抛异常 → 表现为「识别不出来」
- 实测佐证：百度 Key 有效（token 接口正常，scope 含 `vis-ocr_plate_number`），问题不在 Key

### 修改文件
1. `components/nav-header/nav-header.vue`（**核心修复**）
   - 新增 `stripBase64Header()`，调百度前去掉 `data:image/...;base64,` 前缀
   - `chooseImage` 后先 `uni.compressImage(quality:80)` 压缩（规避 base64>4M / 最长边>4096px 限制），H5 不支持则退回原图
   - 全链路补错误处理：token 判空、`words_result` 判空、fail 回调 + `console.error`
2. `common/api/image_ocr.js`（旁路，顺手修正）
   - `grant_type: 'uni.client_credentials'` → `'client_credentials'`；`client_id` 去掉 `uni.` 前缀
   - `method: POST`（未定义变量）→ `'POST'`；`ocrImage` 的 url 由 token 接口改为 `license_plate` 接口
3. `common/api/index.js`：`getToken/ocrImage` 的 import 来源由 `pay_info.js` 改为 `image_ocr.js`
4. `uniCloud-aliyun/cloudfunctions/get_image_ocr_token/index.js`
   - `uniCloud.request`（云函数环境不存在）→ `uniCloud.httpclient.request`，`header`→`headers`
   - 同步去掉 `uni.` 前缀

### 部署 / 注意
- 前端改动，**重新运行**即可生效（OCR 在前端直连百度，不依赖云空间）
- 小程序端：`aip.baidubce.com` 必须加入 request 合法域名；游客 appid(touristappid) 无法配置域名 → 小程序端 OCR 会失败，**App 端不受限**
- 安全：百度 AK/SK 硬编码在前端，建议后续迁移到云函数代理

## 改造：车牌识别 OCR 迁移到云函数代理

### 目标
1. 百度 AK/SK 不再下发到前端（防反编译窃取）
2. 小程序端不需要把 `aip.baidubce.com` 加进 request 合法域名

### 技术前提（已核实）
- **小程序域名**：用 `uniCloud.callFunction` 调云函数走微信**内置云调用通道**，无需配置 request 合法域名 ✅
- **入参上限**：官方文档 —— 阿里云 `callFunction` 的 event ≤ **2MB**（腾讯云 5MB，支付宝云 6MB）
- **httpclient 编码**：`uniCloud.httpclient` 默认即 `application/x-www-form-urlencoded`；`contentType:'form'` 是 **multipart**，不能用

### 改动文件
1. **新增** `uniCloud-aliyun/cloudfunctions/ocr_license_plate/`（index.js + package.json）
   - 一次调用完成「取 token（实例级缓存，提前 10min 过期）→ 调 lease_plate → 返回车牌号」
   - `content: 'image=' + encodeURIComponent(base64)` + `headers: application/x-www-form-urlencoded`
   - token 失效（110/111）自动刷新重试一次
   - 错误码映射为中文（17/18 额度用尽、100 格式错误、282810 无法识别）
   - AK/SK 支持 `process.env.BAIDU_OCR_API_KEY/SECRET_KEY` 覆盖
   - 返回结构对齐项目约定：成功 `{code:200, data:{number,color}}`，失败 `{code:-1, msg}`
2. `components/nav-header/nav-header.vue`
   - 删除 `getOcrToken` / `getOrcResult`（原直连百度 + 硬编码密钥）
   - 新增 `compressForOcr()`：先 `getImageInfo` 取尺寸 → 最长边 1600px 等比缩放 + quality 60；不支持时逐级退回
   - `ocrByPath()` 改为单条 Promise 链：压缩 → base64 → 去前缀 → 体积校验(<1.8MB) → `this.$api.ocrLicensePlate()`
3. `common/api/image_ocr.js`：重写为只导出 `ocrLicensePlate(base64Image)`（调云函数）
4. `common/api/index.js`：导出项由 `getToken,ocrImage` 改为 `ocrLicensePlate`
5. **删除** `uniCloud-aliyun/cloudfunctions/get_image_ocr_token/`（已备份到 `/tmp/get_image_ocr_token_backup_20261013`）

### 校验结果
- 4 个文件语法校验全部通过 ✅；前端已无任何百度 AK/SK 明文 ✅；无残留 `getToken/ocrImage/get_image_ocr_token` 引用 ✅
